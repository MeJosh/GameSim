# 2026-07-23 — Kickoff & architecture

## What we did
Scoped the project and laid the planning foundation: architecture doc, glossary, six
ADRs, the phased roadmap, and a detailed Phase 1 plan. Scaffolded the Python project
with a `core` package of interface stubs and a passing test harness.

## Decisions settled
- **Python-first** stack ([ADR 0001](../docs/adr/0001-python-first.md)).
- **N-agent interface** from day one; two-player is the N=2 case ([ADR 0002](../docs/adr/0002-n-agent-interface.md)).
- **Action masking** is first-class ([ADR 0003](../docs/adr/0003-action-masking-first-class.md)).
- DRL starts with **sb3-contrib MaskablePPO** + self-play ([ADR 0004](../docs/adr/0004-maskable-ppo-via-library.md)).
- **TDD red → green** ([ADR 0005](../docs/adr/0005-tdd-red-green.md)).
- **Deterministic, event-sourced logging** with exact replay ([ADR 0006](../docs/adr/0006-deterministic-event-logging.md)).

## Context that shaped it
The end goal is simplified **Magic: The Gathering**, with **Connect Four** as the first
proving ground. MTG's hard parts (hidden information, stochasticity, huge variable action
spaces, rules-as-data, stack/priority) were used as design pressure so the framework
won't need a rewrite to get there.
